# File tab

- Build a Blank project in a fresh workspace and replace the active workspace only after every frame exists. Bound dimensions, frame count, and positive delay before FFmpeg; delete the candidate workspace on failure.
- Save project archives beside the target under a unique temporary name, close the ZIP completely, recheck cancellation, then replace the destination atomically. Export media to an extension-preserving sibling staging path for the same reason. A missing source, cancellation, or partial write must leave an existing destination byte-for-byte intact and remove the staging file.
- Stream each source frame into the project ZIP with asynchronous, cancellation-aware copies; synchronous archive helpers can block Stop and close deferral for an entire large entry.
- Keep recent projects in an injectable store for tests. De-duplicate by absolute path, order newest first, cap the list, and prune missing paths both from the returned list and persisted state.
- Treat Recents as optional metadata, not a save/load prerequisite. Complete the project archive operation and active-workspace transfer first, then update Recents best-effort and report a non-blocking warning when the per-user configuration directory is unavailable.
- Load and Recent share one path-opening boundary so workspace replacement, recent-list updates, dirty state, error reporting, and cleanup cannot drift. Complete the last cancellable persistence step before swapping the active workspace; cancellation messages must never claim rollback after the old workspace is gone.
- Discard asks for confirmation only when the current workspace carries unsaved work. Build the empty replacement workspace first; cancellation leaves the old timeline, files, selection, and preview untouched.
- Put active-project adoption behind one production lifecycle seam used by Blank, Load/Recent, and Discard. Tests must prove a successful adoption deletes the old workspace and retains the candidate, while adoption failure preserves the old workspace and removes the candidate; scavenger-only tests do not cover replacement cleanup.
- Track one clean frame snapshot after load, save, and discard, and derive dirty state after undo/redo and every mutation. A boolean set to true by every history move produces false discard warnings after Undo returns exactly to the saved state.
- Give each temp workspace a live-process owner marker, scavenge dead owners at startup, and prune unreachable generated edit/transition/paste files when a new edit discards a redo branch. Graceful window-close cleanup alone cannot contain disk growth after crashes or long branching sessions.
- A desktop entry must advertise only launch contracts the process parses. Until file arguments are imported, omit `%U` and MIME associations; quote and desktop-escape installed executable paths, reject characters the supported launcher cannot represent, and quote the Make variable passed to the installer. Validate the generated entry with both `desktop-file-validate` and an actual `gio launch` from a path containing dollar signs, quotes, backticks, and backslashes. All four cross desktop-value and `Exec` parsing layers: the first three need two visible backslashes in the file and a literal backslash needs four. Validator success alone can still leave GLib treating `Exec` as absent.
- Every disabled capture control in both New and Insert groups needs an explicit tooltip naming the out-of-scope capture product. A group-level assumption is not visible to keyboard or pointer users focusing one disabled command.
- Depend on `IFfmpegTool` at every media service boundary, including import, so malformed probe output, zero generated frames, later-source failure, and cancellation are deterministic without an installed process. Real pipeline tests still owe exact fixture frame count/timing and exported packet duration/content; a nonempty recognizable container is not a behavioral oracle.
- Treat project archives as untrusted input. Reject unsafe ZIP paths, missing or malformed manifests, null frame lists, and missing referenced frames with actionable `InvalidDataException` messages, and prove the candidate workspace is removed for every rejection.
- Reserve workspace-control paths before extracting an untrusted archive. In particular, reject a normalized root `.owner` entry: overwriting the live-process marker lets a later application launch scavenge an active loaded project and delete its unsaved files.
- Budget archive extraction before writing: cap entry count, manifest and frame entry sizes, and aggregate expanded bytes; enforce the byte ceiling again while streaming; reject duplicate and unsupported normalized destinations. Path containment alone does not protect shared temp storage from high-ratio or oversized ZIP input.
- Before adopting extracted frames, validate every PNG header's dimensions and the aggregate decoded-pixel workload against the same bounds used for imports. Compressed-byte limits do not constrain a small archive whose images expand into excessive memory, and the rejected candidate workspace must still be removed.
- Keep project save and load budgets symmetric through shared constants. Preflight current frame count and file sizes before creating the temporary archive, reserving manifest capacity, so the editor never reports success and marks clean for a project its own loader must reject.
- Validate the deserialized manifest's frame count directly against the shared ceiling. A ZIP entry-count allowance that reserves an optional `frames/` directory can otherwise admit one extra frame when that directory entry is omitted.
- Represent the active/candidate workspace as an owned disposable object, not a path string. It allocates project artifacts (`frames`, imports, edits, transitions, and pastes), prunes unreachable project files, and makes replacement an explicit ownership transfer. `FrameClipboard` owns a separate disposable workspace for clipboard batches so project replacement cannot invalidate copied frames. A window-maintained list of roots plus service-invented subdirectories will drift; imported redo branches were the first missed class.
- A persisted manifest version is a real compatibility boundary. Save one named current version, validate it immediately after deserialization, and reject unknown newer versions with an actionable message until an explicit migration exists.
- Desktop metadata is user-facing documentation. Advertise only what ships, and revisit it when a capability ships or is withdrawn: the launcher comment was written while recording was unavailable and must change when the Recorder does.
- Preserve animated-image and variable-frame-rate timing from per-frame probe records, reading JSON by named fields. Derive non-final delays from successive presentation timestamps because packet durations can remain constant in a VFR container; use a positive per-frame duration for the final frame and stream-rate timing only when those records are missing or invalid. Applying one average rate or one packet duration to every extracted frame silently flattens real motion timing.
- Preflight media dimensions and counted/estimated frame workload with bounded-output probe metadata before requesting per-frame timing JSON or materializing PNGs. Apply cumulative frame and decoded-pixel ceilings across one import request, and cap extraction at one frame past the limit so inaccurate metadata fails closed instead of consuming unbounded memory or temp space.
- Treat probe metadata as a planning bound, not proof of generated output. Before returning an import, reconcile every generated PNG's actual IHDR dimensions and the actual extracted count against the cumulative decoded-pixel and frame ceilings; underreported media must fail with the whole batch removed. Empty input should observe cancellation and return before allocating an import batch.
- Give concat exports one explicit canvas contract. Probe every frame, center smaller frames on the largest canvas, normalize pixel formats when inputs differ, and round MP4/WebM canvases up to even dimensions for subsampled encoders. Reject GIF delays below its 10 ms timing quantum instead of promising values the codec will coalesce or round.
- FFmpeg's concat demuxer ignores the last entry's `duration`, and FFmpeg 6.1 encodes a repeated final entry as a frame of its own, so the common "repeat the last file" trick exports one frame too many. For GIF and APNG, list one entry per frame and set the last delay through the muxer's `-final_delay` (GIF in centiseconds, APNG in seconds); both muxers refuse a value above 65535 instead of clamping it as they do for interior frames, so clamp it. Video has no per-frame delay to set, so keep the repeated entry there; the extra frame is a copy of the last one and is what gives it its duration. An export test must assert the last frame's duration and the frame count: start timestamps alone cannot see either defect, and a test that pinned the old N+1 packets is what hid the extra frame.
- Concat inputs are PNGs read at the image demuxer's default 25 fps, so every exported delay lands on a 40 ms grid: 66 ms frames alternate 80/40, 33 ms frames stretch to 40, and 16 ms frames are dropped. This is unresolved. Setting `option framerate 1000` on each concat entry removes the grid in testing, at the cost of the last frame's duration, which `-final_delay` now supplies for animated images.
- Force blank-frame generation through a nonsubsampled format such as RGBA before encoding so requested odd dimensions survive the lavfi color source.
- Treat every deserialized project field as nullable regardless of its C# initializer. Validate null frame entries and null/blank paths before dereference, along with the schema version and containment checks.
- Workspace creation during application construction is still a user boundary: catch expected temp-directory I/O/access failures and render a concise recovery window instead of terminating with a stack trace. Scavenging must be wholly best-effort, including root enumeration.
- Route Discard through the same operation/error boundary as other project replacement. Candidate workspace creation can fail before replacement and must report the failure while leaving the active project usable.
